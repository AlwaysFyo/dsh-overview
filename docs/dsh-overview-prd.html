1 · 问题陈述

重度 DSH 用户（单人，多项目并行）当前维护 6 个工作区，会话按工作区分桶存储（~/.dsh/sessions/<工作区路径编码>/）。存在三个真实痛点：

  • 跨项目失控：哪些项目的会话在运行、哪些在等待输入，宿主没有统一出口，需要逐个工作区查看。
  • 上下文恢复成本高：「上次做到哪了」依赖翻找历史会话，会话标题与时间散落在各工作区目录里。
  • 归档即失忆：会话归档后（宿主 archivedSessionIds）几乎不再被回看，缺乏项目级的历史回溯入口；待办散落在会话内容中，容易遗漏。

不解决的代价：每日累积的上下文恢复时间、会话中产生的待办被遗忘、多项目节奏失控。定位：工作台 = 项目仪表盘 + 续接工作入口，而不是又一个 TODO 工具。

2 · 目标

G1 续接效率：从打开工作台到续接任意项目的最近会话，≤ 3 次点击、≤ 10 秒。
G2 首屏即答案：首屏默认视图直接回答「现在哪些项目在跑、哪些有未完成待办」，无需滚动或切换。
G3 归档可回看：任意历史 / 归档会话，可通过项目详情页在 2 次交互内找回。
G4 零破坏：插件默认零修改宿主数据；唯一写入是用户在详情页显式触发的「永久删除会话」，由插件调用宿主 sessionPersistence / workspaceRegistry 服务完成（语义与宿主自身删除一致），卸载插件后宿主功能无损。
G5 待办不遗漏：会话中产生的 todo 事件，被工作台自动收录的比例 ≥ 80%。

3 · Non-goals（本版明确不做）

  • 不做手动任务管理器（新建任务、拖拽排序、甘特图）——待办来自会话推导，不是独立 TODO 应用。
  • 不修改宿主归档机制——archivedSessionIds 的语义与行为完全不动。
  • 不做会话内容编辑；会话永久删除仅限详情页逐条显式操作（见 R2 变更说明），不做批量清理、不做自动回收。
  • 不做移动端 / 多设备同步——DSH 为桌面端单机场景。
  • P0 不做 LLM 项目周报——归入 P2（R9），避免 v1 依赖模型调用。
  • 不做数据导出——P2 再议。

4 · 用户故事

US-1（核心）：作为多项目并行的用户，我想打开工作台就看到所有进行中项目的状态（运行中会话数、待办数、最近活动），以便决定先续哪条线。

US-2（核心）：作为用户，我想点击项目卡片进入项目详情页，按「进行中 / 历史 / 归档」三组浏览会话，以便找回上下文。

US-3（核心）：作为用户，我想从会话列表点击某条会话直接跳回宿主续聊，以便不用手动切换工作区翻找。

US-4：作为用户，我想看到从会话自动提取的待办清单并勾选完成，以便不遗漏会话中产生的承诺。

US-5：作为用户，我想把不再活跃的项目标记为已归档，以便首屏只关注活跃项目。

US-6：作为用户，我想在已归档分组里仍能查看项目的全部历史会话与待办，以便「归档不等于失忆」。

US-7：作为用户，我想用一次搜索跨所有项目查找会话与待办，以便不记得在哪个项目时也能找到。

US-8（空态）：作为新用户（无项目或无会话），我需要看到引导文案与「新建会话」入口，而不是空白页面。

US-9（边界）：作为用户，当工作区目录被删除或移动时，我希望对应卡片降级显示（置灰 + 「路径失效」提示），而不是报错崩溃。

5 · 需求

5.1 P0 —— 没有就不能上线

R1 · L1 全局卡片墙P0US-1 / US-5 / US-9
  • 顶栏：标题「工作台」+ 跨项目搜索框 + 全局指标胶囊（运行中 N、待办 N，仅统计进行中项目）。
  • 状态分段器：「进行中 · N / 已归档 · N / 全部 · N」三页签，默认停在「进行中」。
  • 项目卡片（统一三段式）：① 标题行（状态点 + 项目名 + 状态说明）；② 路径；③ 三格指标（活跃会话 / 待办 / 未提交 git 数）+ 最近会话摘要行。运行中项目用蓝色实心状态点 + 较深边框强调。
  • 已归档卡片降饱和：虚线边框、空心状态点、透明度降低、显示「归档于 xx-xx」。
  • 排序：进行中页签按最近活动时间倒序。
AC-1：Given 6 个工作区且 1 个会话运行中，When 打开工作台首屏，Then 默认显示「进行中」页签，运行中项目状态点为蓝色、指标数值正确，已归档项目不出现在该页签。
AC-2：Given 某工作区目录已删除，When 渲染卡片墙，Then 该卡片置灰显示「路径失效」且不参与指标统计，页面无报错。
AC-3：Given 无任何工作区，When 打开首屏，Then 显示空态引导文案 + 「新建会话」入口。
R2 · 项目级归档标记（status.json）P0US-5 / US-6
  • 存储：~/.dsh/dsh-overview/status.json，结构 { "schemaVersion": 1, "<工作区 path>": { "archived": bool, "archivedAt": ISO 时间 } }。
  • 交互：卡片右键 / 悬浮菜单提供「归档 / 恢复」；已归档卡片可一键恢复。
  • 自动建议：项目 30 天无活动且无运行中会话时，卡片角落出现「归档？」轻提示，仅建议，点击才生效，绝不自动归档。
红线（三条）：① 项目归档不触碰宿主 sessions 目录与 workspace.json；② 归档不级联会话级归档，两套标记各管各的；③ 归档完全可逆，status.json 损坏时回退默认态（全部视为进行中）并重建文件。
AC-4：Given 项目 A 被归档，When 比对宿主 workspace.json，Then 内容与归档前逐字节一致。
AC-5：Given status.json 被手工破坏，When 启动插件，Then 回退默认态、重建文件并提示一次，不崩溃。
实现变更（2026-11-01，v0.1.1 已上线）：本节的项目级归档（status.json）未实现并已撤销。实测宿主 workspace.json 的 global.archivedSessionIds 是归档真相（归档缓存只是历史快照），因此工作台改为两条显式写入路径：①「归档 / 取消归档」委托宿主 workspaces.archiveSession(id,{stopActivity:true}) / unarchiveSession(id)；②「永久删除」调用宿主 sessionPersistence / workspaceRegistry 服务，级联仅限 subagent 子会话，绝不级联 fork。插件不再拥有独立归档状态文件（src/host/statusStore.ts 已删除）。已归档会话允许同时是 live 会话，聚合层以宿主集合作准、归档缓存仅作元数据兜底。
R3 · L2 项目详情页P0US-2 / US-3 / US-6
  • 顶部：「← 返回」+ 项目切换下拉（每项带状态点，项目间切换 ≤ 1 秒）。
  • 四指标卡：活跃会话 / 待办 / 已完成 / 今日 token（数据不足的卡片隐藏，不留空壳）。
  • 会话三 tab：「进行中 / 历史 / 归档」，归档 tab 数据源 = 宿主 archivedSessionIds；各 tab 内按最近活动倒序，显示会话标题、轮次数、相对时间、运行状态点。
  • 点击会话 → 跳回宿主该会话续聊（复用宿主会话打开 API）。
AC-6：Given 项目有 27 个历史会话、3 个归档会话，When 切换三个 tab，Then 各 tab 数量与列表正确、排序为最近优先。
AC-7：Given 处于任意项目详情页，When 点击进行中会话，Then 宿主打开该会话且工作台状态保持（返回后不重新加载丢失位置）。
R4 · 跨项目搜索P0US-7
  • 范围（P0）：项目名、会话标题 / 摘要、待办文本；P0 数据量小，实时扫描即可，不建索引。
  • 结果按项目分组展示、命中词高亮，点击直达对应会话或待办。
AC-8：Given 关键词命中 2 个项目的 3 条会话，When 搜索，Then 按项目分组展示、命中高亮，且归档项目的结果在「全部」语义下可达。
R5 · 空态与异常兜底P0US-8 / US-9
  • 三类空态（无项目 / 无会话 / 路径失效）+ 两类异常（status.json 损坏、sessions 目录读取失败）均有降级文案，任何情况下不白屏、不阻断宿主。
AC-9：Given sessions 目录临时不可读，When 打开工作台，Then 显示「数据暂不可用」降级态，宿主主流程不受影响。

5.2 P1 —— 紧随其后的快速迭代

R6 · 待办提取与勾选P1US-4
  • 来源优先级：① 宿主 todo 工具事件（可订阅则监听）；② 会话产物解析（markdown checklist 等）兜底；③ 手动添加作为补充。
  • 待办归属项目 = 产生它的会话所在项目；勾选完成状态写入 dsh-overview/todos.json（第二处写入点）。
AC-10：Given 会话内产生 3 条 todo，When 打开该项目详情页，Then 待办面板收录 ≥ 80% 且标注来源会话。
R7 · git 集成（只读）P1US-1
  • 项目卡片与详情页显示分支名、未提交文件数；实现为只读 git status，节流调用（切页时刷新，不做文件监听）。
R8 · 项目动态时间线P1US-6
  • 详情页右侧展示事件流：长会话结束、文件提交、会话归档、待办完成；仅聚合已有事件，不引入新数据采集。

5.3 P2 —— 架构留位，本期不实现

R9-R12 · 增值能力P2
  • R9 LLM 项目周报：「本周做了什么 / 下一步」自动摘要（依赖模型调用，P0 架构上预留事件数据即可支持）。
  • R10 token 成本趋势：跨项目按日 / 按项目聚合图表（依赖 .dshw-usage.json 粒度验证结论）。

  • R12 闲置项目提醒：N 天无活动 + 有未完成待办时在首屏提示。

6 · 数据设计

数据源读写用途
~/.dsh/storages/workspace.json只读工作区注册表：path / title / sessionIds / archivedSessionIds / pinnedSessionIds
~/.dsh/sessions/<slug>/session-*/只读会话元数据、轮次、时间戳 → 推导活跃 / 历史 / 最近活动 / 摘要
~/.dsh/storages/session_projcache_archive_manager_v2只读归档会话数据（详情页「归档」tab）
~/.dsh/.dshw-usage.json只读token 用量（粒度待验证，见开放问题 Q1）
git 仓库（只读 status）只读分支名、未提交文件数（P1）
~/.dsh/dsh-overview/status.json写入项目归档标记（唯一 P0 写入点，可逆、可自愈）
~/.dsh/dsh-overview/todos.json写入（P1 起）待办勾选状态（提取内容仍来自会话）

核心原则：状态靠推导，不靠手工维护——除上述两处插件自有文件外，一切展示数据来自宿主现有存储的只读推导。两个自有文件（status.json / todos.json）均携带 schemaVersion 字段，便于后续结构演进与迁移。

7 · 成功指标

层级指标目标与测量
北极星「从工作台续接」的会话占全部续接行为的比例上线 4 周后 ≥ 60%（插件内埋点计数）
驱动首屏 → 续接点击路径长度≤ 3 步达成率 100%（交互设计保证，上线时验收）
驱动待办周勾选率上线 4 周后 ≥ 50%。
健康插件崩溃次数 / 宿主启动时间增量崩溃 0；启动增量 < 200ms（对比开关插件各测 10 次）
健康归档误操作恢复成本恢复归档 ≤ 1 次点击（设计保证）

附录 A · 设计定稿记录（2026-10-31 三轮评审）

  • 信息架构（定稿）：L1 全局卡片墙（跨项目聚合）→ L2 项目详情（三 tab 会话 + 指标 + 待办）→ L3 会话（跳回宿主续聊）。放弃一屏主从方案；触发回退的边界条件：项目数长期 ≤ 3 且单项目为主。
  • L1 布局（v3 定稿）：状态分段器（进行中 / 已归档 / 全部，默认进行中）+ 统一三段式卡片 + 全局指标胶囊；归档卡片降饱和（虚线边框、空心状态点、「归档于 xx-xx」）。迭代原因：v1 状态区分不明显、v2 卡片参差。
  • 项目级归档语义（定稿）：手动标记 + 30 天自动建议（仅提示不执行）；三红线 = 不动宿主数据、不级联会话归档、完全可逆。
  • 定位（定稿）：项目仪表盘 + 续接工作入口；状态推导优先，工作台不是 TODO 工具。
