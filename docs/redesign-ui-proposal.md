# 全景概览 · UI 改版方案（参照飞书多维表格主页）

> 状态：**方案待拍板**（2026-11-01）。目标页 = L1 全景概览（`src/client/App.tsx` 顶栏 + `views/Wall.tsx` 卡片墙）；
> L2 详情页本期只继承设计 token，不动结构。

## 0. 方向一句话

把现在的「顶栏塞满胶囊 + 三格数字卡片墙」改成飞书多维表格主页那种**两层页头 + 最近优先 + 信息行**的仪表盘：
一屏先回答「我该继续哪个会话」，再回答「一共有哪些工作区」。

从飞书主页搬过来的 5 个特征（其余不动）：

1. **极浅底 + 纯白卡**，靠边距和留白分层，不靠灰底方块堆层次。
2. **一个主色**（蓝）只用于主操作、运行中状态、选中态；其余全部中性灰。
3. **卡片用 meta 行**（`4 会话 · 3 待办 · 12 分钟前`），不用三格灰底数字块。
4. **操作在 hover 时才出现**（行尾 `⋯` / `预览` / `打开`），静止态干净。
5. **「最近访问」优先于「全部」**——首屏第一块内容是可直接点进去的会话，不是分类筛选器。

## 2. 新信息架构

```
命令条（sticky，48px）      品牌 · 搜索⌘K · 运行中/待办/诊断 · 主题 · 新建项目 · 新建会话
────────────────────────────────────────────────────────────

  ① 继续工作               5 条最近会话（会话级直达）
  ② 工作区                 下划线 tab + 排序 + 卡片/列表（视图切换在项目区内）
```

关键取舍：**统计数字不再做成顶栏胶囊**，改成页头副标题里的一行文字。顶栏只留两个带状态色的可点计数（运行中 / 待办），因为它们能当筛选入口用。

## 3. Header 布局

### 3.1 线框（宽屏 ≥1280）

```
┌──────────────────────────────────────────────────────────────────────────────────────────────┐
│ ◆ 全景概览  ⌕ 搜索项目、会话、待办 ⌘K    ● 2 运行中  待办 15  ⚠ 11 诊断  ☾  ＋新建项目  ＋新建会话 │ 48px sticky
├──────────────────────────────────────────────────────────────────────────────────────────────┤
│  工作区                                                                                       │ 页头
│  9 个工作区 · 37 个会话 · 2 个运行中 · 数据 22:41 更新                                          │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```

- 命令条：`height: 48px`，`padding: 0 24px`，`gap: 16px`，底 1px `--wb-line`；滚动 > 8px 时加 `0 1px 8px rgba(31,35,41,.06)`。
- 左：品牌块（18px 圆角方块 + 14px/600 文字），宽度固定，不参与挤压。
- 中：搜索 **默认 260px，聚焦展开到 360px**（`transition: width 160ms`），占位符带 `⌘K` 提示；不再 `flex: 1` 拉满。
- 右（`margin-left: auto`）：状态组三个可点文字计数（`● 2 运行中` / `待办 15` / `⚠ 11 诊断`，12px，颜色只落在状态点与数字上，无胶囊底色）+ 主题按钮（32×32 图标）+ 竖分隔线 + 两个创建入口：`＋ 新建项目`（描边次按钮）+ `＋ 新建会话`（蓝底主按钮）。
- 诊断计数沿用现有 `diagnostics`（`cacheIssues` + `unclaimed` 之和），点开仍是诊断抽屉；为 0 时整颗隐藏，不显示「0 诊断」。
- 两个创建按钮都需要宿主侧创建能力。现有注入只有 `openWorkspace` / `openSession`（打开既有对象），**实现前必须先确认 `uiWorkspace` 有没有新建方法**；没有就改为打开宿主的创建入口，再拿不到就隐藏——不做点了没反应的假按钮。

### 3.2 页头（非 sticky）

- `h1` 22px/600，`letter-spacing: -0.2px`；其下 13px `--wb-ink-2` 的统计行。
- 页头右侧**不再放视图切换**：卡片/列表是项目区的视图状态，跟着数据走（见 4.3），页头只回答「我在哪 + 全局数字」。
- 页头整体随内容滚动，**不吸顶**——吸顶会有 96px 常驻占位，而这里没有需要常驻的操作。

### 3.3 窄屏（<900px）

品牌只留方块；搜索塌缩成 32×32 图标，点击后覆盖成整行搜索（popover 全宽）；状态组只留数字（含诊断）；两个创建按钮只留 `＋`，靠 `title` 区分。

### 4.3 tab、排序与视图

- 状态分段器仍是**下划线 tab**（与 L2 详情页一致），与「工作区」标题同处一行；右端固定顺序：排序 ▾ → 设置 → 视图分段。

### 4.4 勾选框

现状：三处原生 `<input type="checkbox">`（`Detail.tsx:687` / `801` / `975`），只有待办 feed 在 `themeCss.ts:487` 给了 `accent-color`，其余全是浏览器默认方头蓝勾，和这套 token 完全不搭。

对齐飞书多维表格（Base）的勾选框——Base 里的勾选框**很轻**，存在感低，只在需要时才「亮」：

| 项 | 规格 |
|---|---|
| 尺寸 | **16×16**，圆角 3px，点击热区 20×20（Base 没有灰底方形热区，只有手型光标） |
| 描边 | 1px `--wb-cbx-line`（浅色 `#D5D8DC` / 深色 `#4A4E55`），未选中几乎不抢眼 |
| hover | 仅描边加深到 `--wb-ink-3`，不改底色 |
| 按下 | `scale(.88)`，120ms，给点击一点物理反馈 |
| 勾选 | 填充 `--wb-accent`、描边同色，上盖 **12×12 内联 SVG 勾**（路径照抄 Base 的 `ud__checkbox__checked-svg`） |
| 半选 | 同填充 + 12×12 SVG 横杠（路径照抄 Base 的 `ud__checkbox__indeterminate-svg`） |
| 焦点 | 3px `--wb-accent-bg` 外环（键盘操作才出，鼠标点击不出现）——**这是唯一有意偏离 Base 的地方**，Base 自己不做 focus 环，但这里是无障碍硬要求 |
| 禁用 | `opacity: .4`，`cursor: not-allowed` |
| 大一号 | `.cbx-16` → 18px / 圆角 4：批量条用 |
| 深色 | 不新增规则，全部走 token；勾用 `--wb-accent-ink`（`#0E1524`）而不是白色，避免在 `#6E9BFF` 上刺眼 |

- 实现方式：原生 input 视觉隐藏（1px + `opacity: 0`，保留可聚焦与读屏语义），相邻 `<span class="cbx">` 画框，框内放两个 12×12 内联 SVG（`.ck` / `.ind`），用 `input:checked + .cbx .ck { display:block }` / `input:indeterminate + .cbx .ind { display:block }` 切换——这就是 Base `ud__checkbox__wallpaper` 的结构。**不用 `appearance: none` 直接改 input**：input 是替换元素，`::after` 在 Chrome 上不可靠，且 `indeterminate` 只能由脚本设置。
- 勾形**用内联 SVG**：不用 `mask` + data URI（第一版就是这么翻车的：mask 一失效就退化成「实心蓝块没有勾」），也不用两条边框拼（16px 框里 12px 的勾，边框拼法的粗细和端点都对不上 Base）。
- 选中行：`--wb-accent-bg-weak` 浅蓝底（浅色 `#F2F6FF` / 深色 `#1B2333`）+ `aria-selected="true"`；**不加左侧竖条**——Base 的选中行就是纯底色，竖条是我上一版自创的。
- 出现时机（Base 的做法）：按 Base 习惯**默认不出现**，常驻显示会让整列显得很重。列表行在 hover / 已选中时露出；卡片视图在 hover / 聚焦 / 已选中时用勾选框**替换项目图标**（同一个 20px 格位，绝对定位覆盖，不重排、不抖动）；列表表头全选常驻（半透明 60%，hover 到 100%）。
- 键盘可达：勾选框本体是原生 input，`Tab` 能到、`Space` 能切；`:focus-within` 同样触发展示，纯键盘用户不会「看不见勾选框」。
- 全选：表头 16px 勾选框，部分选中走 `indeterminate`；点击语义是三态（全选 → 全不选）。
- **两个视图共享同一份选择**：按项目 id 绑定，卡片里选过再切到列表，对应行已经是选中的；批量条计数按项目去重。
- 待办勾选：勾上后标题 `line-through` + `--wb-ink-3`，条目延迟 1.2s 淡出而不是立刻消失（给撤销留时间）。
- 落点：`themeCss.ts` 新增 `.wb-cbx` 组件类 + `--wb-cbx-line` / `--wb-accent-bg-weak` 两个 token；`Detail.tsx` 三处原生 input 替换；待办 feed 删掉 `accent-color`。
- L1 项目级批量（勾选框 + 底部批量条）：**接口先行**——宿主目前只有会话级 `POST /dsh-overview/session/batch`，项目级归档/恢复/删除没有写入口，先补 `POST /dsh-overview/project/batch`（`{ action: 'archive' | 'unarchive' | 'delete', projectIds }` → `BatchResult`；archive 语义 = 该项目全部会话进 `global.archivedSessionIds`，不新增项目级字段；delete 需二次令牌且「删项目到底删什么」尚未定）。接口落地前 L1 不出真批量动作，不做假按钮。UI 侧卡片与列表两个视图都提供勾选（共享选择），批量条固定底部。

## 5. 配色

## 6. 交互体验

### 6.1 键盘

| 按键 | 行为 |
|---|---|
| `⌘/Ctrl + K`、`/` | 聚焦搜索 |
| `Esc` | 关闭搜索 / 清空 → 再按返回 L1 |
| `↑ ↓` | 搜索结果内移动；卡片墙/列表内移动焦点 |
| `Enter` | 打开当前项（会话=预览，卡片=详情） |
| `1 / 2 / 3` | 切换 进行中 / 已归档 / 全部 |

### 6.2 指针

- 卡片 hover：描边 `--wb-line-strong` + `--wb-shadow-2`，**不位移**（9 张卡同时上浮会晃眼）；`transition: 120ms ease-out`。
- 行 hover：底 `--wb-surface-2`，行尾 `⋯` 淡入（`opacity 0 → 1`，80ms）。
- 点击热区：卡片整卡可点；行内 `⋯` 为 24×24 且与行点击互不冒泡。
- 焦点环：`2px solid var(--wb-accent)` + `2px offset`，键盘可见、鼠标不出现。

### 6.3 搜索

- 默认收起；聚焦展开 360px，下方弹层 420px 宽、`max-height: 60vh`。
- 空输入聚焦 → 显示「最近 5 条会话」（复用继续工作数据），不显示空白框。
- 结果分三组：工作区 / 会话 / 正文（正文命中沿用现有 320ms 防抖与开关）。
- 结果项 36px 高，两行（标题 + `正文 · 助手 · 会话名`）；`mark` 用 `--wb-accent-bg` 底 + `--wb-accent` 字。

### 6.4 动效

- 时长：hover 120ms、tab 切换 120ms 淡入、抽屉 220ms `cubic-bezier(.16,1,.3,1)`。
- 卡片首次渲染 stagger 20ms × 最多 8 项；`prefers-reduced-motion: reduce` 下全部关掉。
- 加载：6 张骨架卡（`--wb-surface-2`，1.2s 呼吸），不居中 spinner。

### 6.5 空态与降级

- 无工作区：图标 + 一句说明 + 主按钮，居中，`padding: 72px 0`。
- 筛选无结果：一行 `该分组下没有工作区 · 切到全部`（可点）。
- 路径失效：整卡**不降透明度**（现在 `.is-dead { opacity: .55 }` 会把文字压到不可读），改为标题行右侧 amber 标签「路径不存在」+ 虚线描边。
- 运行中：左缘 3px 蓝条 + 状态点；不加整卡蓝底。
- 数据来源告警（`state.warnings`）：页头统计行末尾追加 `· 3 项降级`，点击开诊断抽屉。
